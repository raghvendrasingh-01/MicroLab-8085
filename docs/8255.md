# The 8255 PPI in MicroLab

## Addressing

The 8255 occupies four consecutive I/O addresses — set the base in the
inspector (default **80H**):

| Offset | Register |
|---|---|
| +0 | Port A |
| +1 | Port B |
| +2 | Port C |
| +3 | Control register |

`OUT 80H` writes Port A, `IN 82H` reads Port C, `OUT 83H` writes the
control register — routed by the I/O bus, so the base can be moved anywhere
in the 256-address space without touching your program logic (only the
constants change).

## The control word

```
 D7  D6  D5  D4  D3  D2  D1  D0
 │   └───┬───┘ │   │   │   │   │
 │ Group A mode│ PA │PCu │ PB │PCl │
 │             dir │dir │ dir │ dir │dir
 └ 1 = I/O mode (this simulator's mode word)
```

- **D7 = 1** — mode definition word. D6-D5 select the group A mode
  (**00 = Mode 0** is fully simulated; 01/1x = Mode 1/2 are *not* — see
  below). D4 = PA direction (1 = input), D3 = PC upper (PC4-7), D2 = PB
  direction, D1 = PC lower (PC0-3).
- **D7 = 0** — bit set/reset (BSR) word: D3-D1 select a PC bit, D0 sets or
  resets it. Useful for pulsing control lines (ADC ALE/START, LCD EN).

Common words:

| Word | Meaning |
|---|---|
| `80H` | all ports output |
| `90H` | PA input, PB/PC output |
| `98H` | PA + PC upper input, PB + PC lower output (the ADC handshake setup) |
| `82H` | PA output, PB input (the keypad scanner setup) |

## Modes

**Mode 0 (basic I/O)** — complete: both port groups, live direction
changes, output data registers (a port configured as output reads back what
was last written, like the real ODR), input ports read pin levels live.

**BSR (bit set/reset)** — complete: writing base+3 with D7=0 sets or resets
one PC pin. Note that in BSR mode the data *direction* of PC stays whatever
the last mode word set.

**Mode 1 / Mode 2 (strobed I/O, bidirectional bus)** — *not simulated.*
The control word is accepted and the direction bits take effect, but the
handshake lines (STB, IBF, OBF, ACK, INTR) do not function. Selecting them
raises a console warning and the diagnostics panel flags it. If you need a
handshake, do it in software: wire the peripheral's status line to a PC pin
and poll it (see the ADC experiment).

## Wiring recipes

**Drive a device** (LEDs, 7-segment, LCD data, DAC, keypad rows):
mode word with the port as output, wires `PA0..PA7 → D0..D7`.
Shift-click wiring connects all eight in one gesture.

**Read a device** (switches, keypad columns, ADC data, scope probes): port
as input, wires from the device's outputs into `PA0..PA7`. An input port
with nothing wired reads `00H` (the net is pulled low).

**Handshake bits**: use PC lower as outputs (control lines) and PC upper as
inputs (status lines) — the `98H` word. PC pins are individually wireable,
and BSR words let you pulse one bit without touching the others.

## On the card

The 8255 card shows the current byte on each port, the control word, and
each port's direction. Select it to change the base address (the I/O bus
refuses a move onto an occupied window).
